# Answers of the forum's app API, as test data

`forum_v2_*.json` (forum page, `schema: 2`), `thread_v3_*.json` (thread page, `schema: 3`), `index_v5_*.json` (forum index, `schema: 5`), `profile_v4_*.json`
(profile page, `schema: 4`: the account's own page, two other members, a lookup by username, the guest and the unknown
user messages), `search_v6_*.json` (search results, `schema: 6`: the first and second page of a search, a search without
a result), `guide_v7_*.json` (guide pages, `schema: 7`: every list view, the guide index with its modules, the guest asking
for "my" threads) and `mythread_v9_*.json` (the "my threads" pages, `schema: 9`: the threads on two pages, the replies, the
draft box, the guest), `favorite_v8_*.json` (the favorites, `schema: 8`: the threads on two pages, the forums, an empty
list, the guest), `friend_v10_*.json` (the friends lists, `schema: 10`: the own list on two pages, another member's list,
an empty list, the guest), `pm_v11_*.json` (a private message conversation, `schema: 11`: a one-page conversation, page 3
of 4 of a longer one, a group conversation, a member never written to, the guest) and `credit_v12_*.json` (the credit log,
`schema: 12`: two pages, a filtered page, the guest) are real answers of the `tsdmapp` plugin, fetched from a test forum
and scrubbed. They are regenerated by a tool kept with the plugin, not by hand: the tool fetches every case again, drops `document`/`head`, rewrites the test
forum's host and name (and, on the profile page, the viewer's own IP rows), and normalizes the fields that change on
every request so the tests can pin them:

- `formhash` → `f1f2f3f4`
- `reply.posttime` → `1700000000`
- `thread.views` → `100`
- `activity.lastvisit` → `1700000000`, `activity.lastactivity` → `1700000060`, `checkin.last` → `1700000000` (profile page)
- `searchid` → `1`; the top-level `checknewpm` url's `rand` → `1700000000`; the fixture-made draft thread → tid `9199982`, subject suffix `00000`, times `1700000000`
- favorites: the fixture-made `favid`s are renumbered from `251` in order; friends: `online`/`lastactivity` → `0`
- `stats.todayposts` → `100`, `stats.yesterdayposts` → `50`, every forum's `todayposts` → `0`, `red_packet.dateflag` → `20261001` (index page: these change every day)
- `searchid` → `1`, the `rand` of `checknewpm` → `1700000000` (search results: the forum numbers every search)
- the 2.5.0 groups (the favorites, the friends, the conversation, the credit log) pin `formhash` and the `rand` of
  `checknewpm` the same way; their records were made by the plugin's fixture script with fixed times, so nothing else
  changes between fetches

`forum_v2_fid2.json`, `thread_v3_plain.json`, `profile_v4_self.json`, `index_v5_member.json`, `search_v6_results.json`,
`guide_v7_new.json`, `mythread_v9_thread.json`, `favorite_v8_thread.json`, `friend_v10_me.json`, `pm_v11_view.json` and
`credit_v12_log.json` carry a deliberate garbage `document`: the tests prove the structured

`write_v13_*.json` (the results of writes, `type: result`, `schema: 13`, plugin 2.6.0: a reply stored, refused by the
flood control, by a guest, by a thread gone (a message page) and stored without AJAX (a redirect); a rate taken and
refused, the rate form (a page); a favorite added, added again, removed, and the success page; a friend request sent
and sent again; a report; a private message; the profile saved (a page with the frame script); the check-in plugin's
window, today and again) are the plugin's answers of the same requests, scrubbed the same way (the test forum's host →
`https://www.tsdm39.com/`, its name → `测试论坛` as in the other fixtures, `formhash` → `f1f2f3f4`; the post, favorite
and record ids as sampled). Beside each one, `write_v13_*.orig.txt` is what the forum answered the very same request
without the parameter (the status line, the content type and `Location`, a blank line, the body). For every reader
switched to the result the tests run both and expect the same outcome, except where the forum's own answer cannot
tell it: the favorite posted without AJAX (`favorite_msg`: the whole 提示信息 page has no hook, so the old parser
reports its text as a failure while the result tells the success; the app always posts with `inajax=1`) and the reply
posted without AJAX (`reply_redirect`: a 301 the client does not follow for a POST, a failed request as before, while
the result names the new post); the tests pin both outcomes. `write_v13_formhash_bad.orig.txt` is the forum's "System
Error" page of a bad form hash (never JSON); its back trace id and System Info block (the machine and the server
versions) are replaced by fixed text. `write_v13_reply_ok.json` carries a deliberate garbage `document`: a `handle`
never reads one.

`thread_v14_*.json` (the thread page with each floor's bbcode, `schema: 14`, plugin 2.7.0: a plain thread; the
fixture thread with its first floor of every tag and attachment, hidden, password, free, payment, `bbcodeoff`, raw
html and literal floors, seen by a member, the author, a guest without attachments, a guest of a forum showing guests
thumbnails, a member who may not view images, and in a forum with jammer; a paid thread; a reply hidden from the
viewer; a moderated reply; a thread of smilies and a jsonEditor floor; a banned author's floor; a single-banned floor
seen by a moderator; floors whose ids another floor's html forged (`spoofed`); a custom code with a hidden part,
`[index]` and an attachment id with a leading zero) and `thread_v14_smilies.json` (the `smilies` action) are copied from the plugin's 2.7.0
contract samples and scrubbed the same way (host, name, `formhash`, `reply.posttime` → `1700000000`, `thread.views`
→ `100`). `forum_v2_fid29_pending.json` is hand-written (the pending-application
message).

`special_v15_*.json` (the thread page with the special block of the first floor, `schema: 15`, plugin 2.8.0: polls
single and multiple, results shown after a vote, voted, expired, an image poll, a guest, the author, a moderator, a
banned and a forged first floor; goods seen by the author, a member, a moderator, a guest and with only one author's
floors; bounties open (the author, a member, a guest) and resolved, the accepted answer hidden from the viewer
(replies only the author sees, `[hide]`, `[password]`, a banned author) or seen by the author or a moderator,
anonymous; activities open, applied, accepted, asked to complete, closed, with credit enough or not, seen by the
author and a guest; debates open (a member, a guest, the umpire), voted, ended with the umpire's verdict, without an
end time, without the first floor, page 2 for a member who argued on a side and for one who never replied, with the
side taken in `reply.stand`) are copied from the plugin's 2.8.0 contract samples and scrubbed the same way (host,
name, `formhash`, `reply.posttime` → `1700000000`, `thread.views` → `100`); only the cases the tests use are kept.
`special_v15_*_action.json` are the results (`type: result`, plugin 2.6.0) of the real actions of the same run: a poll
vote, an activity application and its cancel, a best answer and a debate vote;
`special_v15_reward_bestanswer_refused_action.json` is the forum's refusal of a second best answer, from the plugin's
acceptance run (`evidence/special280.json`). On the profile answers the tool also pins the viewer-dependent values: `activity.lastvisit`/`lastactivity`
(and the same rows in `profile_html`), `checkin.last` (and the check-in row), the IP ports. Everything else must not be edited by hand; change the plugin or the tool instead.

Since plugin 2.8.2 the tool's groups `index`, `index_fav`, `forum` and `thread` were fetched again from the test forum
running 2.8.2 (the forum descriptions as html, `redirect`/`private` of the categories and the subforums, `allreplies`,
each floor's `avatar_blocked`/`hot`/`hot_position`). `*_282_*.json` (`index_v5_282_*`: forum 7 with a description of
activity links, a link forum 25, a forum 26 the viewer may not enter; `forum_v2_282_*`: subforum 15 with a thread link
in its description, as a link forum and as a forum the viewer may not enter, forum 11 asked past its last page and past
the site's limit of pages (`threadmaxpages` 3), and its last page under that limit; `thread_v15_282_*`: the thread of
the acceptance fixture with the avatars of banned authors hidden, with two hot replies, and with one author's floors)
are answers of the plugin's 2.8.2 acceptance run (`evidence/audit282.json`), scrubbed with the tool's own functions
(`scrub`, `normalize`, `normalize_thread`, the index group's pins), as the fixtures of the special threads were.

`post_v16_*.json` (the forms of a new thread, a reply and an edit asked in the JSON mode, `type: post`, `schema: 16`,
plugin 2.9.0: a new thread in a forum without types, with required types (the moderators' type left out), moderated,
of a thread sort, of a poll, and in a forum where another plugin prints fields of its own (`hook_fields`); a reply, a
quoting reply, a reply to an anonymous thread and the reply window (`infloat=yes`, without `inajax`); the edits of a
first post, a reply, a post with an image and a file attachment, a draft, a poll and a jsonEditor post; the messages
of a guest, of an edit of another member's post and of a password forum) are fetched from the test forum by the
plugin's contract tool (`tools/fixtures.py --group post`) with its fixture script (`postfix290.php`: every id of the
threads, posts, attachments and poll options it made is pinned to a constant, 9600001…, 9700001…, 9800001…, 1001…, and
the suffix of its marker strings to `000000`) and scrubbed the same way; `submit.fields.posttime` → `1700000000`,
`noticeauthor` (the forum's encrypted note, new on every request) → `NOTICEAUTHOR`, `formhash` → `f1f2f3f4`, the upload
hash → 32 zeros, the key of an attachment's thumbnail url → `00000000`, the time of a quoted post → `2023-11-15 06:13`.
The forms of forum 2 that open a thread (the new threads of forum 2, the edits of its first posts) list the test
forum's form plugin in `hook_fields`; the tests take them as a forum without such a plugin serves them by clearing it.
`post_v16_newthread.json` carries a deliberate garbage `document`: the structured path never reads it.
