# TSDM Client 屏蔽功能設計（修訂版）

2026-09-21｜依使用者「對方不知道、單方面屏蔽」要求修訂；使用者已以 go 核准實作

## 使用者需求與修訂原因
兩種功能都要，由 Claude 實作，Codex 驗收並與 Claude 討論。
使用者補充：黑名單需要對方不知道，以單方面屏蔽為主。
Claude 與 Codex 檢查上游後確認：論壇黑名單會刪除好友關係，可能拒絕對方私訊及加好友，因此不適用於這個需求。

## 1. App 靜默屏蔽用戶（取代論壇黑名單同步）
- 在他人資料頁提供「屏蔽此用戶」，以用戶 UID 識別，不以暱稱判斷；禁止屏蔽自己。
- 名單僅保存在 App 本機，依登入帳號隔離；重新啟動後保留。網站與其他裝置不會自動同步。
- App 主題列表及搜尋結果隱藏被屏蔽作者的主題；帖子中將其回覆摺疊為簡短佔位，保留樓層與跳轉定位。引用等可識別來源的內容亦需避免直接顯示，無法判定來源的文字不能宣稱全面過濾。
- 直接開啟被屏蔽作者的主題時，顯示已屏蔽提示及返回／解除入口，不直接呈現內容。
- 提醒中可可靠識別來源為被屏蔽 UID 的項目隱藏，並抑制 App 對應的提醒提示；不能靠正文任一用戶連結猜測來源。管理頁清楚說明舊通知若缺少來源資料，過濾有其限制。
- 好友關係、私訊收發權限、伺服器未讀狀態均不因本機屏蔽而改變；不呼叫論壇黑名單介面、不向對方發送通知。
- 本版保留私訊會話，不新增私訊拒收或自動已讀。對方仍可正常互動。
- 管理頁可檢視／解除，解除後重新顯示本來仍可取得的內容。
- 不宣稱對方在任何情況下都無法推測；產品可保證的是不主動通知、不改變論壇互動權限。

## 2. 論壇屏蔽提醒（獨立功能，保留原需求）
- 通知選單支援「此人的這類提醒」與「所有人的這類提醒」，使用論壇真實 type、authorid 及表單。
- 直接同步論壇提醒過濾規則，可列出與解除，不聯動論壇黑名單。
- 只影響之後產生的提醒，不自動刪除歷史通知或標成已讀。
- 解除一條規則前讀取最新隱私表單，保留所有其他已勾選的通知、動態、好友分組欄位，避免整組覆寫遺失。
- 舊快取缺少可靠屏蔽資料時不猜測；新欄位採可空及相容遷移。

## 3. 介面
- 用戶資料頁：屏蔽／解除屏蔽。
- 自己的資料頁選單：「屏蔽管理」，分為「已屏蔽用戶（本機）」及「屏蔽提醒（論壇）」；文字說明兩者儲存範圍。
- 通知卡選單：「屏蔽此類提醒」；通知頁提供管理捷徑。
- 遵循現有 App 樣式，提供繁中、簡中、英文文案。

## 4. 驗收與討論
- 本機屏蔽操作完全不發送黑名單／解除好友請求；UID 比對準確、不誤傷同名用戶、禁止對自己操作。
- 名單帳號隔離、重啟保存、切換帳號後即時更新，讀取失敗不錯誤覆蓋既有名單。
- 主題、回覆、直接連結、搜尋、可判定來源的提醒和 App 提示一致；空列表、分頁及樓層定位正常。
- 屏蔽與解除不改變伺服器已讀狀態，不影響收件、發件與好友功能；本地可見未讀數與歷史記錄維持一致。
- 論壇提醒表單成功／錯誤／登入失效／格式差異及帳號切換；解除規則保留其他隱私欄位。
- 通知資料相容、遷移及多帳號同步回歸；不混入 review_only 故意失敗測試。
- Claude 實作 → Codex 審查並執行測試 → 具體問題交 Claude 討論／修正 → Codex 重驗。報告區分已測、未測與線上驗證限制。
