# 銀行第一階段

從個人資料頁進入銀行，依論壇列表選銀行，顯示已開戶狀態、活期摘要、論壇錢包可用餘額、利息與注意事項。使用者可讀取自己／收到的交易記錄及翻頁。未開戶銀行直接提供網頁辦理入口。

第一階段原生交易限活期存入與取出；開戶、修改銀行密碼、定存、匯款、貸款、積分交易及手動結息保留網頁入口。理由是這些動作各有不同資料與確認流程；本次僅確認活期表單。既不把網頁包裝成完成所有銀行功能，也不猜未觀察到的提交參數。

介面：銀行清單 → 活期摘要／交易記錄 → 輸入正整數金額及銀行密碼 → 確認銀行、幣別、存取方向及金額 → 一次提交。取消任何步驟不送出。小數／超長貼上整筆拒絕，不把 1.5 改成 15。密碼不持久保存、不加入狀態與日誌，離開對話框釋放輸入控制器。

實作採獨立 bank models／repository／cubit／view，沿用既有網路供應器與帳號隔離。路由 `/bank`，繁中、簡中、英文三語。無資料庫遷移。模型只解析銀行專屬區塊；日誌不保留網站額外顯示的 IP。

安全邊界：所有 GET 僅允許銀行清單、活期、日誌。所有回應須驗證與目前登入 UID 相符；切帳號立刻清資料，丟棄舊回應。交易只接受同源銀行端點、正確銀行 ID／action、完整且啟用的指定表單欄位；缺任何必要值、幣別或遇到未知格式就停用原生交易。線上瀏覽工具未提供 hidden bankid/action 的值，因此不根據畫面路徑填入推測值，由 App 實際回應確認。

送出前以同一個帳號綁定的 repository 重新 GET 表單，檢查帳號、銀行及幣別，再用伺服器當次提供的欄位送出一次 POST。不可重送 POST；操作中鎖住連點與導覽觸發。成功或網路錯誤都只以 GET 刷新餘額／記錄。未觀察到可核對的銀行成功回應格式，因此不憑 HTTP 200 或餘額差值報成功，明確顯示結果待核對；刷新不抹去這個提示。

銀行 POST 明確指定 singleAttempt：Dio 禁止跟隨轉址，Android 將策略經 method channel 送到 OkHttp 專用 client，停用連線重試與轉址並使用 one-shot body。這防止原生層對 408／503／307 等回應自行重送；其他請求維持原策略。交易前檢查至結果刷新期間阻止頁面返回，避免送出後丟失結果提示。

驗證：匿名樣本解析、危險／未知表單拒絕、金額與幣別、帳號隔離、舊回應、確認過期、連點、網路逾時不重送、取消對話框、窄螢幕及密碼遮罩回歸測試；全測試與嚴格分析。真實帳戶存取款由帳號持有人在測試版驗收，本次不挪動使用者論壇貨幣。
