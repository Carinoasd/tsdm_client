# 銀行完整功能

依使用者「把功能全搞了，再叫他測試」擴充 #120，交付 Android 測試版，不合併正式版。原有銀行／活期／日誌保留；新增營業資訊與開戶、定期、匯款、貸款、帳戶管理、手動結息、跨銀行帳戶總覽、排行。積分買賣目前由論壇停用，顯示伺服器原因，不虛構可用交易。

銀行頁以服務選單切換，每個服務獨立載入，失敗可重試；日誌失敗不清空已讀餘額，提交後的日誌刷新失敗也不抹掉已刷新的餘額。日誌解析容許真實表格內的分頁列並保持空資料與錯誤頁的區別。定期／貸款資料以伺服器區塊與表格呈現，保留本金、期限、利率、狀態及記錄的關聯，不依賴活期餘額存在。

原生活期流程繼續使用既有模型；新增通用但限於銀行服務的表單模型。只接受同源銀行 POST、對應銀行／服務、明確伺服器隱藏欄位、支援的金額／天數／收款人／密碼欄位。定期支取及貸款記錄操作只使用當筆伺服器表單的識別欄位與按鈕，不自行生成記錄 ID 或操作值；不認識的控制元件保留明確網頁入口。未知 JavaScript 或 GET 操作不自動執行。

實際 response HTML 已核對：cur/in,out；cur/ok 結息；fix/in 定存；chg/ok 匯款；len/try 申貸；pas/cg 改密碼；pas/cl 銷戶；open 開戶。瀏覽器 DOM 會遮蔽 hidden value，因此規格以 Network response body 為準。開戶費用及各項利率採伺服器文字。定存至少30日、匯款至少10，整數精確驗證，密碼與確認必須一致。匯款費用可依頁面公布的費率計算並註明以論壇實際結算為準。

所有交易採輸入與最終確認兩階段。确认包括銀行、操作、記錄內容、金額／天數／收款人、費用／注意事項；不顯示密碼。送出前同一帳號 client 重讀服務頁，比對表單識別、欄位、幣別、費用與記錄內容；改變即拒絕並要求刷新。POST 單次、禁止重試與轉址，仍沿用目前 Android／Dio 已驗證的傳輸政策。回應仍按「尚未確認結果」處理，只讀刷新；密碼只在對話框及送出期間存在，不存入狀態或日誌。

UI 為原生 Flutter 卡片、資料列及表單，窄螢幕可捲動；登入／切帳號取消舊資料與確認，送出中阻止離頁。新增欄位使用繁中、簡中、英文。伺服器提供的內容保持原文。

驗證限定有意義的回歸：真實空紀錄／分頁結構、部分失敗保留資料、服務解析與各種表單拒絕條件、同帳號新表單單次送出、帳號／銀行／費率／記錄變更中止、密碼遮罩、表單取消及窄螢幕。完成後一次完整測試及嚴格分析，推 #120，僅打 Android 預覽包，交測試者驗收實際交易。開发期間不操作論壇資金、不改密碼或銷戶。
