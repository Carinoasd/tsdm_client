# 每日红包与登录积分（#110、#111）

## 已确认范围

- 设置 → 签到加入默认关闭的独立开关，自动为当前账号领取每日红包；与原有所有账号自动签到互不影响。
- 开启应用、重新加载首页或共用首页资料的分区页时执行。缓存命中不执行，不新增后台任务。
- 补做网页提供的每日登录检查，不写死奖励金额，不在本地修改积分。

## 诊断依据

`test/data/forum_index_x5.html` 是此前捕获并脱敏的真实论坛首页，其中有
`home.php?mod=spacecp&ac=pm&op=checknewpm&rand=...` 外部脚本。
客户端解析 HTML，不会执行该脚本。

本地 Discuz 参考源码 `source/app/home/child/spacecp/pm.php` 的 `checknewpm` 分支，在已登录且
`newpm` 状态符合条件时调用 `updatecreditbyaction('daylogin', uid)`；网页正常响应为空 JavaScript。
这是上游机制的依据，不代表已检查线上论坛的私有源码。实际金额、次数及资格仍由服务器判定；
本次测试以真实页面样本和模拟响应验证客户端流程，尚未实机确认线上 2 天使币入账。

## 实现

首页仓库复用获取页面时绑定账号的网络客户端，依序调用每日登录检查、可选红包领取，成功后至多
重新获取一次首页，使余额及红包入口反映服务器结果。后续请求失败保留原页面；账号切换则丢弃旧页面。

仅允许同源 `/home.php` 且参数限定为 `mod=spacecp&ac=pm&op=checknewpm` 与可选 `rand`，
拒绝额外或重复参数、其他协议、来源及片段，不执行任意 JavaScript。

红包使用既有接口与页面 formhash。按账号及论坛 `dateflag` 去重，服务器明确返回成功或已领取才记录；
失败仅限制一分钟内重复请求，之后刷新可重试。登录检查同样有一分钟间隔，避免请求风暴，不用
本地午夜决定奖励日期。重启后重新信任服务器页面与幂等接口。并发请求共用进行中的奖励流程。

## 验证

- 真实首页脚本解析及请求白名单。
- 独立开关、默认关闭、持久化、旧备份兼容。
- 游客、账号不匹配、切换账号、执行中关闭开关。
- 同日去重、论坛换日、账号隔离、并发合并及失败重试。
- 首页 → 登录检查 → 红包 → 单次刷新完整请求与既有积分提醒流。
- 请求失败时首页及手动入口保留。
